## Verification boundaries

The high-confidence credential scanner checks tracked text source for supported token formats and private-key headers, printing only file/line and category. It does not scan Git history, detect every secret format, prove credential rotation, or certify privacy. GitGuardian checks are independently configured in GitHub; their results are separate evidence.

Static review found fixed auth callback destinations, server-derived identity, user-scoped repositories, RLS/grant migrations, single-use expiring OAuth state, encrypted provider tokens, text-only email rendering, validated/grounded AI outputs, bounded calls and daily reservations. These controls still require hosted negative-case verification. No custom cryptography or new provider was introduced.

Account export remains bounded. Retention is request-triggered; no guaranteed scheduled deletion is claimed. Demo state is fictional and process-local/shared. A strict CSP and HSTS rollout require actual HTTPS/runtime policy testing; this patch does not invent a policy that could break Next hydration or OAuth.

Clean installation initially hit npm 10.9.2's peer resolver `edgesOut` error. npm 11.6.2 repaired resolution; npm 10 regenerated missing optional dependency entries and then completed `npm ci`. Keep the lockfile and verify clean CI installation rather than rely on an existing node_modules tree.

Use BETA_READINESS.md for remaining release gates. Final exact test/audit counts are recorded with the delivery evidence; upstream severity is not a claim of confirmed application compromise.
