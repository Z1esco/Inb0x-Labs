## Design and implementation

The dark attention desk retains Sora, Manrope, Space Grotesk and its existing semantic
palette. Spenza informs the wide product stage, recurring 1240px container, varied
chapters and trust-to-CTA sequence. Its assets, phone presentation and violet identity
are not copied. Actual browser research covered [Spenza](https://s-penza.app),
[Landdding](https://landdding.com) and [Motionin](https://motionin.design); authenticated
source inspection and exact provenance are in [V2_FRONTEND_PLAN.md](V2_FRONTEND_PLAN.md).

The landing page now presents an original hero, three actual product views, a selectable
source/evidence/decision example, evidence and reply stories, a route directory, factual
read-only boundaries, FAQ and demo/sign-in paths. Six desktop/mobile captures show our
actual application with fictional fixtures. Mobile images focus on the relevant working
surface and display their full portrait frame. Static image imports provide versioned
build assets. No new runtime dependency was added.

Dashboard wording follows empty, singular and plural attention queues; its total is
labelled stored threads. Dashboard and Insights share proportional volume bars, including
true zero heights and visible count/date labels. Insights avoids unsupported urgency
claims. Task editing is labelled; task and saved-reply deletion require confirmation.
Inbox, thread, login and settings retain their existing architecture and behavior.

Static marketing composition remains a Server Component. Navigation, product selection
and the educational walkthrough are small client components. Interactions use native
buttons, links and disclosure, explicit state and short feedback transitions. There are
no autoplay timers, scroll-driven reveals, background API calls or animation dependencies.

390×844, independently of the detector. It judged the design authored for Inb0x, with
low cognitive load and a pre-correction Nielsen score of **26/32**. Assessment B reviewed
360×800, 768×1024 and 1440×900, React boundaries, charts, images and controls. Its findings
were withheld until A finished. The detector ran once across the five specified targets:
exit 0, JSON `[]`, zero findings. This does not certify visual quality or accessibility.

Corrections from these reviews:

- Replace the 300px mobile crop with the complete portrait frame; recapture the actual
  analysis and reply at useful scroll positions so their content is visible.
- State explicitly that the educational excerpt omits the sent date and timezone;
  require checking the full message before scheduling a relative deadline.
- Change the navigation trigger's accessible name when expanded.

The IAB review could not finish a native confirmation check because its CDP connection

The Impeccable overlay was skipped because the exposed IAB evaluation API is read-only.
No overlay server was started. A later root inventory showed no remaining IAB tabs,
and the temporary browser viewport override was successfully reset.

## Verification results

- `npm run check`: passed formatting, zero-warning ESLint, strict TypeScript,
  **30 unit test files / 230 tests**, and the Next.js 16.4.0 production build.
- `npm run test:e2e`: **30 passed**, Chromium and WebKit, with **126 route screenshots**.
- `npm run audit:production`: **0 vulnerabilities**. A fresh full audit still reports
  **5 high development-tool advisories**, previously documented in
  [SECURITY_AUDIT_2026-10-11.md](SECURITY_AUDIT_2026-10-11.md). V2 changes no dependencies.
- `npm run security:scan`: **0 findings across 243 tracked files**.
  `git diff --cached --check`: passed. The scanner checks selected tracked text formats,
  not Git history or every possible credential format.

The matrix covers landing, login, dashboard, inbox, thread, tasks, drafts, insights and
settings at exactly **360×800, 390×844, 768×1024, 1024×768, 1280×800, 1440×900,
1920×1080** in Chromium and WebKit. It asserts loaded content, no horizontal document
overflow, reduced-motion behavior, loaded landing imagery, no page/console errors during
each route inspection, and reply-body contrast of at least 4.5:1. Separate journeys cover
demo entry/reset/exit, task creation/completion, explicit analysis/acceptance, source
navigation, reply generation/copy, navigation focus/Escape, deletion cancellation,
error recovery, empty search and configured privacy headers.

The first full browser run passed 23/30. One assertion still expected the old landing
heading after demo exit; it now checks the destination and new heading. WebKit skipped
implicit navigation anchors during Tab traversal; a focused probe showed explicit
`tabIndex={0}` preserves the expected order. Navigation links now declare it, and sign-in
has a 44px target. The other failures occurred when repeated `page.goto` calls cancelled
the previous document's pending Next prefetches. A diagnostic recorded cancelled
`Next-Router-Prefetch: 1` requests alongside WebKit access-control page errors. The matrix
now opens an independent page per route and retains every error assertion; user navigation
remains covered by separate journeys. No error text is filtered and no browser security
setting or application prefetch policy was weakened. Similar teardown behavior is
[reported upstream](https://github.com/microsoft/playwright/issues/42823); attribution to
a particular browser/framework defect remains unverified.

Final desktop and mobile renders were inspected after correction. Selected committed
captures: [desktop landing](screenshots/v2-landing-1440.png),
[mobile landing](screenshots/v2-landing-390.png). The complete 126-capture matrix,
